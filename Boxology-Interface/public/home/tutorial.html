Tumor Diagnosis walkthrough

Use this page to understand the full Tool4Boxology loop: model a NeSy system, validate its Boxology patterns, generate a knowledge graph, query it, and produce documentation.

Scenario

A clinician wants explainable tumor diagnosis support.

The system learns from annotated MRI scans, uses a trained model for new images, and produces a diagnosis that can be inspected against the symbolic structure of the workflow.

Boxology reading

Three patterns form one pipeline.

  • Labeling: Expert + Engineering -> Label for Segments.
  • Training: Label for Segments + Preprocessed MRT Data + Train -> Supervised Model.
  • Detection: MRT Image + Supervised Model + Deduce -> Diagnosis.
The pipeline

Five steps from diagram to queryable knowledge.

These are the same steps you can repeat for your own neural-symbolic architecture.

Draw and group the design

Place typed components on the canvas, connect them, then cluster each input-process-output unit into a named design pattern.

Tip: use the Boxology elements page when you need to decide whether something is data, a symbol, a model, an actor, or a process.

Validate every pattern

Check Validation compares each grouped pattern with valid Boxology combinations. For this example, the tool confirms Engineering, Train, and Deduce are valid in their typed contexts.

Create the knowledge graph

Once the diagram validates, Tool4Boxology transforms it into RDF. The system, patterns, components, processes, inputs, and outputs become graph resources connected by the T4B vocabulary.

Ask SPARQL questions

The SPARQL panel includes examples and a free-form editor. For instance, you can ask which pattern produced Label for Segments.

PREFIX t4b: <http://tool4boxology.org/>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

SELECT * WHERE {
  ?pattern t4b:hasOutput ?output ;
           rdfs:label ?patternLabel .
  ?output rdfs:label "Label for Segments" .
}
QuestionAnswer
Which pattern produced Label for Segments?Labeling

Explore and document the result

The KG viewer lets you click each pattern and inspect its type, validity, matched pattern, inputs, and outputs. The documentation generator then produces a concise system summary directly from the graph.
