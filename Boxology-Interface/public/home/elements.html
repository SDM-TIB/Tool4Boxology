Notation guide

Boxology elements

Use this page as a quick reference when deciding which shape belongs in a Tool4Boxology diagram. The key habit is to model the role of a component, not only its name.

Core vocabulary

The five component roles.

These roles let Tool4Boxology validate whether an input-process-output pattern is meaningful for a neuro-symbolic system.

Data

Data

Concrete observations, files, measurements, images, tables, signals, or datasets. Example: MRT Image or Preprocessed MRT Data.

Symbol

Symbol

Meaningful concepts, labels, rules, classes, diagnoses, or knowledge-level statements. Example: Diagnosis or Label for Segments.

Actor

Actor

A person, expert, agent, or external system that performs or contributes knowledge. Example: Expert.

Process

Process

An action that transforms or infers from inputs. Example: Train, Deduce, Transform, or Engineering.

Model

Model

A learned, statistical, symbolic, or hybrid model used by another process. Example: Supervised Model.

Pattern

Group related components.

A design pattern is a meaningful input-process-output unit. Tool4Boxology validates these grouped units, not isolated boxes.

Validation

Use types to catch mistakes.

If a process expects data and receives a symbol, or produces the wrong kind of output, validation can flag the mismatch.

Reuse

Name patterns clearly.

Good names make the resulting knowledge graph easier to query, document, compare, and reuse across architectures.
